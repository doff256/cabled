# Run R7: auto-rotation and auto-framing (2026-11-21)

## What was built
| Piece | Where |
|-------|-------|
| **Auto-rotation** on the phone: `AVCaptureDevice.RotationCoordinator` gives the angle that keeps the horizon level, applied to the capture connection (the hardware rotates for free). The encoder is recreated when the frame flips between landscape and portrait | `ios/Cabled/Video/VideoPipeline.swift` |
| **Face detection** on the phone (camera hardware, `AVCaptureMetadataOutput`, D-10). Boxes are rotated into the sent frame's coordinates and attached to every VIDEO message as JSON metadata: `{"faces":[{id,x,y,w,h}]}`. Stale detections (> 0.5 s) are sent as none | same |
| **Framer** (pure, unit-tested): primary face (sticky by id, else most prominent), head-and-shoulders crop at the output's aspect ratio with headroom, quality guard (never crops below the output's pixels unless max zoom allows upscaling), dead zone, critically damped springs (calm glide, the same feel at any fps), hold 2 s after losing the face, then ease back to the full view | `windows/src/engine/framing.*` |
| **Aspect fill:** with framing off, or no faces, the output is the largest centred crop with the app's aspect ratio. A portrait phone fills a landscape camera instead of being squashed | `fillCrop` |
| **Converter crop:** crops on even pixels by shifting plane pointers. A crop exactly the output's size is a straight copy | `windows/src/engine/frame_convert.*` |
| **Negotiation:** framing on → ask the phone for ~2× the output (4K for 1080p) so crops stay sharp | `negotiator.*` |
| Engine: one crop drives both Cabled Camera and the preview. `setFraming()`; status reports faces seen. C API `cabled_engine_set_framing`. App: **Auto-framing** switch (on by default, R-42), `--debug-faces` draws the detected faces in the preview | engine, `cabled_core`, app |

CPU path note: cropping and scaling still run on the CPU (swscale), which is fine at these rates. The GPU version is an optimisation for later and changes nothing above the converter.

## Tests
Framer: fill crop for landscape/portrait/4:3 sources, disabled = full view, face framing with headroom and no upscaling, wider shot for bigger faces, dead zone vs real moves, smooth motion (no jumps), hold then return, max zoom, stays inside the frame. Negotiator: framing asks for 2×. Engine: faces in VIDEO metadata reach the framer, and framing can be switched off. Swift: VIDEO metadata framing, face-box rotation. **63/63** Windows tests.

## Owner test (iPhone build 6)
1. Install build 6 ("0.1.0 (6)"). Close Cabled on the PC if it's open, then start it with the face overlay:
   ```powershell
   C:\Users\Doff\Documents\Cabled\app\Cabled.App\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\Cabled.exe --debug-faces
   ```
2. **Rotation:** turn the phone between landscape (both ways) and portrait. The picture should stay upright, with a short glitch at each turn while the encoder restarts. Portrait fills the frame (cropped), not squashed.
3. **Faces:** green boxes should sit on faces in every orientation. If they're mirrored or rotated wrongly in portrait, tell me which way: the rotation direction is the one thing the simulator can't check.
4. **Framing:** sit in view. The picture should glide to frame you (head and shoulders, some headroom) and follow when you move, but not twitch. Leave: it holds for 2 s, then eases back to the full view. Switch auto-framing off and on.
