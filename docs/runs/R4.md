# Run R4: a resilient engine and the first Cabled window

**Goal** (roadmap.md): the engine as a long-running service that finds the phone, survives every disconnect, pause and hang, tells the user (and the apps using the camera) what's going on, plus a minimal WinUI 3 app on top. Together with R3's iPhone half, this makes **M1**.

**Status (2026-11-21):** done on the Windows side and tested against the fake phone. 39/39 tests pass locally, and the engine tests passed 4 repeats with no flakiness. Not yet run with a real iPhone: the R1 phone test is still blocked by the SideStore sign-in outage.

## What was built

| Piece | Where |
|-------|-------|
| **Engine** (replaces R3's single-threaded session): connection thread (find phone → connect → handshake → receive, reconnect with backoff), decode thread (bounded queue, overflow → keyframe request), housekeeping thread (pings, watchdog, status cards, stats) | `windows/src/engine/engine.*` |
| **States** from architecture.md: no-service, no-device, waiting-for-companion, connecting, incompatible, streaming, paused, error. Each has a headline plus a next step | `EngineState`, `EngineStatus` |
| **Status cards in the camera** (R-73): when there's no live video, apps see a card such as "Open Cabled on your iPhone" at the size they chose. The headline shrinks to fit small frames | `windows/src/engine/status_card.*` |
| **Pause handling:** phone STATUS `{"session":"interrupted","reason":…}` → Paused with a reason-specific message, `{"session":"running"}` → resume. The connection is kept | engine + protocol doc |
| **Watchdog:** no message for 5 s (pongs count) → drop and reconnect, so a hung phone can't freeze the camera forever | housekeeping thread |
| **C ABI** for the app: create/start/stop, JSON status, BGRA preview frames, log lines | `windows/src/core_api/cabled_core.*` → `cabled_core.dll` |
| **Cabled app** (C# .NET 10, WinUI 3 / Windows App SDK 2.7, unpackaged, self-contained): status line with coloured dot, device line, live preview (WriteableBitmap, 960 px), stats footer, virtual-camera state. Preview is paused while minimised. `--tcp ip:port` talks to the fake phone | `app/Cabled.App/` |
| Fake phone misbehaviour: `--disconnect-after`, `--pause-after/--pause-for`, `--freeze-after`, `--drop-every` | `windows/src/common/fake_phone.*` |
| `cabled-engine` CLI now runs the engine (Ctrl+C to stop) | `windows/tools/engine/main.cpp` |
| **Virtual camera DLL fix:** an engine frame in the wrong format (for example mid-switch) used to stall delivery. It's now skipped and the repeat/placeholder cadence carries on. The selftest uses a private ring (`CABLED_VCAM_RING`) | `windows/vcam/` |

## Tests (all against the fake phone, no Frame Server)
`Engine.DecodesFakePhoneStreamInOrder`, `HardwareDecodeWhenAvailable`, `RecoversFromLostFrames` (F9), `ReconnectsAfterDisconnect` (F1), `PausesAndResumes` (F5, no reconnect), `WatchdogDropsSilentPhone`, `ReportsRefusedConfigure`, `WaitsWhileNobodyAnswers`, `StatusCard.RendersReadableText`, `StatusCard.LongHeadlineFitsSmallFrames`.

Found and fixed along the way: the watchdog used unsigned time arithmetic, so a message stamped between two clock reads looked like 584 years of silence and dropped healthy connections.

## Measured (app's engine → Cabled Camera → `cabled-vcam check`)
- Live: 421/422 frames from the engine over 14 s, 30.1 fps, capture → app **median 2.4 ms**, p95 4.9 ms.
- Fake phone killed → the camera shows **"Waiting for the phone"** within a second or two. The fake phone restarts → reconnects and resumes on its own.
- Fake phone "backgrounded" → camera shows **"Cabled is in the background on your iPhone · Open it again to resume"**, then resumes on the same connection.

## Known gaps / next
- **Pending on your side:** reinstall the virtual camera DLL so Frame Server gets the stall fix. The UAC prompt was cancelled today, so the R2 DLL is still installed.
  ```powershell
  .\windows\scripts\vcam-dev-install.ps1
  ```
- Apps that mirror their self-view show the status card's text mirrored *to you*. The other side of a call sees it the right way round. Common to all webcam placeholders; revisit if it confuses people.
- The UI is deliberately minimal: no settings, no tray, no start at login. Those come in R9/R11. The preview is a CPU WriteableBitmap until the GPU pipeline (R7) gives the app a SwapChainPanel.
- USB detection polls ListDevices every second while disconnected. The usbmux `Listen` push events are a later refinement.
- Windows needs ~2 s to report "refused" for a TCP port nobody listens on, so fake-phone reconnects are slower than USB ones will be.

## Try it (no iPhone needed)
Build the C++ side and the app once:
```powershell
cmake --build build --config Release
```
```powershell
dotnet build app\Cabled.App\Cabled.App.csproj -c Release
```
Then start a fake phone that pauses after 10 s and comes back 5 s later:
```powershell
.\build\bin\Release\cabled-fakephone.exe --clip windows\testdata\pattern_1080p30.h264 --pause-after 10 --pause-for 5
```
And the app, pointed at it:
```powershell
.\app\Cabled.App\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\Cabled.exe --tcp 127.0.0.1:47800
```
Watch the status line go Connecting → Streaming → Paused → Streaming. Close the fake phone window and see it switch to waiting and reconnect when you start it again. Pick Cabled Camera in OBS to see the same status cards there.
